# 内容规范与匾额校核

> 适用于 `js/data/info.js` 与 `js/palace.js` 的挂匾配置。
> 目标不是写百科，而是让每一条都能被核查、不夸大、不虚构。

---

## 一、词条字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 中文名，必须与匾额、侧栏一致 |
| `en` | 是 | 英文名，采用故宫官方常用的意译 |
| `cat` | 是 | 前朝 / 后寝 / 东路 / 西路 / 城防 / 宫外 |
| `year` | 是 | 始建或重建年代，格式见下 |
| `form` | 是 | 屋顶形制与院落格局 |
| `scale` | 否 | 面阔、进深、通高等；不确定的标“示意” |
| `status` | 否 | 现状用途，只在有把握时填写 |
| `desc` | 是 | 史实说明，40–120 字，重点殿宇 80 字以上 |
| `note` | 否 | 考据说明、争议点、示意标注 |

### 写作约定

- **年代格式**：`明永乐十八年（1420）`；重建用 `明永乐十八年（1420）／清康熙三十四年（1695）重建`。
- **术语统一**：面阔、进深、重檐、庑殿、歇山、攒尖、十字歇山（释义见下）。
- **不写无法核查的数字**。场景是示意复原，不是测绘成果；六宫面阔统一标“（示意）”。
- **有争议的内容进 `note`**，不塞进正文伪装成定论。
- **不写“最美”“最大”之类营销词**。太和殿“现存最大木结构殿宇”属学界通说，可保留。

## 二、术语表

| 术语 | 含义 | 场景是否实现 |
| --- | --- | --- |
| **面阔** | 建筑正面的开间总宽，间数即开间数 | — |
| **进深** | 垂直于面阔方向的深度，常以椽架计 | — |
| **重檐** | 两层屋檐，下层檐环绕屋身，等级高于单檐 | 是（`double: true`） |
| **庑殿** | 四面坡、一条正脊四条垂脊，官式建筑中等级最高 | 是（`style: 'hip'`） |
| **歇山** | 上部两面坡、下部四面坡，一条正脊、四条垂脊、四条戗脊 | 是（`style: 'xieshan'`） |
| **悬山** | 只有前后两坡，山墙处屋面不出挑 | 是（`style: 'gable'`） |
| **攒尖** | 各坡向中心汇聚于宝顶，无正脊，多用于方亭、圆亭 | 是（`style: 'pyramid'`） |
| **盝顶** | 顶部为平顶，四周做坡檐 | **否**。`createHall` 未实现，词条不得声称某建筑为盝顶 |
| **十字歇山** | 两个歇山顶十字相交，角楼即此形制 | 是，但不是 `style` 参数：角楼用两个 `roofGeometry` 正交拼合手工搭建 |
| **举折** | 屋面从檐口到屋脊由缓渐陡的凹曲线 | 是（`curv`） |
| **翼角起翘** | 屋檐转角处向上翘起，是明清官式建筑的典型特征 | 是（`lift`） |
| **推山** | 庑殿顶将正脊向两端延伸、使垂脊转折的处理 | 是（庑殿推山系数 0.76） |

> 写词条前先看“是否实现”一列。场景没做的形制，`form` 里不能写，否则信息卡会与模型对不上。

## 六、考据边界

1. 本项目的三维模型是**示意复原**，不是测绘成果。开间数、院落尺寸与真实建筑存在偏差。
2. 词条只写通说，不采用孤证；有争议的细节写进 `note`，例如长春宫《红楼梦》壁画的作者与题材至今仍有讨论。
3. 现状用途会随展览调整而变化，`status` 只写相对稳定的信息（如“原状陈列”“参观出口”）。
4. 不引用具体书目页码，避免制造“精确引用”的假象；如需学术引用，应另行核对原书。
5. 场景中的建筑位置服从构图与性能，不保证与实测坐标一致；但**中轴序列不得错位**（午门—太和门—三大殿—乾清门—后三宫—御花园—神武门—景山—寿皇殿）。
