# 无障碍自查报告

> 对应 v2.0 的无障碍改造，v2.1 补搜索 / 已阅 / 指北针 / 沉浸模式，v2.4 补探索清单 / 朝代对比 / 第一人称，v2.5 补画布文本替代、状态播报与标签分组后复核。
> 检查范围：键盘可达性、焦点可见性、ARIA 标注、减少动效、触控目标。
> 结论：主流程可仅用键盘完成；v2.5 给画布补了文字摘要与状态播报，剩下的最大缺口是**摘要只是名字列表，不描述方位与空间关系**，以及尚未用真实读屏软件走查。
> 数字口径：侧栏 97 条可交互词条（`node tools/stats.js` 的「已阅分母」）；建筑标签按 `REGISTRY` 实体生成，同名角楼不去重，数量随内容增长。

### 焦点顺序

`Tab` 顺序按 DOM 结构走：左上角视角按钮 → 侧栏（搜索框 → 97 条索引项）→ 工具条 → 日照条与播放键 → 探索清单 / 朝代对比面板（在 `#info` 之前入 DOM）→ 建筑标签 → 指北针 → 信息卡。两个面板与侧栏互斥，`body.quests-on` / `body.eras-on` 下侧栏 `display:none`，焦点不会停在看不见的控件上；`body.fps-on` 下轨道 UI 全部 `display:none`，只留退出按钮。

**v2.5 的标签分组解决了逐个 Tab 的冗长**：按 `[` / `]` 或点「标注 · 全部」选中一个分类后，非本组标签设 `tabIndex = -1` 并隐藏，键盘只在本组标签间移动；切回「全部」恢复。`#a11y-status` / `#scene-alt` / `#search-status` 是 `.sr-only`，不进 Tab 顺序，也不影响截图。搜索结果重排只搬动 DOM 节点，事件监听与焦点绑定不重建。

### 焦点可见性

- 所有按钮、侧栏项、指北针、建筑标签均有 `:focus-visible` 金色描边；搜索框用金色边框 + 背景加深表示聚焦（`outline` 已关闭，避免双线）。
- 建筑标签的描边加在 `.lbl-body` 上，避免描边被裁切。
- 信息卡打开时不会强制抢焦点，避免打断键盘浏览。
- `H` 沉浸模式下界面元素同时设 `visibility: hidden`，焦点不会停在看不见的控件上；再按 `H` 即恢复。

## 二、ARIA 与语义

| 元素 | 处理 |
| --- | --- |
| 工具按钮 | `aria-label` + `title`，双语同步 |
| 自动旋转 / 标注 / 昼夜流转 | `aria-pressed` 反映开关状态 |
| 建筑标签 | `role="button"`、`tabindex="0"`、`aria-label="太和殿，查看详情"` |
| 侧栏条目 | `role="button"`、`tabindex="0"`；已阅项加 `✓`，不计入无障碍名 |
| 搜索框 | `type="search"` + `aria-label`，随语言切换 |
| 已阅计数 | `title` 说明"已阅词条 / 总数"，纯展示不设 `aria-live`（避免每次翻词条都朗读） |
| 指北针 | `role="button"`、`tabindex="0"`、`aria-label` 说明"点击使视角朝向正北" |
| 信息卡 | `role="region"`、`aria-live="polite"`、`aria-labelledby` 指向标题 |
| 导览字幕条 | `role="region"`、`aria-live="polite"`，换站时朗读 |
| 提示条 | `role="status"`、`aria-live="polite"` |
| 探索清单 / 朝代对比面板 | `role="region"` + `aria-label`；触发按钮 `aria-expanded` / `aria-pressed` |
| 朝代 tab | `role="tablist"` / `role="tab"`，`aria-selected` 与 `tabindex` 联动，支持 `←` / `→` |
| 清单条目 | 原生 `<button>`，`aria-pressed` 表示是否已阅；勾选刷新就地改属性，不重建 DOM、不丢焦点 |
| 一次性完成提示 | `role="status"` + `aria-live="polite"`，带可聚焦的关闭按钮 |
| 第一人称准星 / 匾额 | 准星 `aria-hidden="true"`；匾额浮层 `aria-live="polite"`；准星点中建筑时再把名称播报进 `#a11y-status`（漫游中信息卡隐藏，读屏读不到它） |
| 操作提示 | `role="status"`，写明 `WASD` / `Shift` / `Esc` 退出路径 |
| 画布文本替代 | `<canvas aria-describedby="scene-alt">` + `#scene-alt`（`role="region"`，约 2 秒刷新尺度、可见标注名、选中建筑；`aria-live` 关闭，避免持续播报） |
| 状态播报 | `#a11y-status`（`role="status"` + `aria-live="polite"`）：标注分组切换、漫游准星选中 |
| 搜索结果播报 | `#search-status`（`role="status"` + `aria-live="polite"`）：写入「找到 N 条」，含 0 条；`#no-result` 的可见文字不变 |
| 标注分组按钮 | 动态 `aria-label` / `title` 双语，`aria-pressed` 表示是否处于分组状态 |
| 页面语言 | `<html lang>` 随中英切换更新；canvas 与画布摘要的 `aria-label` 一并切换 |

## 三、减少动效

`js/views.js` 的 `Views.reducedMotion()` 读取 `prefers-reduced-motion: reduce`：

- 机位切换由弧线飞行改为直接落位。
- 导览换站同样直接落位，不做强制镜头飞行。
- CSS 在减少动效下关闭过渡与动画（含新加的搜索框、指北针与沉浸模式过渡）。
- 自动旋转默认关闭，不受该设置影响。
- **昼夜流转不自动开始**：它只由用户点按或 `?play=1` 触发，减少动效用户不会被强制拉进动画。水面波纹属环境动效，跟随日照联动，无法单独关闭；如需完全静止可用 `?still=1`。
- **v2.4 新界面无过渡**：清单 / 朝代面板与漫游 UI 都用 `display` 切换，没有淡入淡出；第一人称只由按键驱动，不含自动镜头动画。因此 `prefers-reduced-motion` 下这些功能行为不变。
- **v2.5 未引入动效**：搜索结果重排是 DOM 即时移动，命中高亮只改边框 / 背景色，分组切换不播镜头动画；`prefers-reduced-motion` 下行为一致。

## 五、已知缺口

1. **画布摘要只是文字列表**：`#scene-alt` 给出尺度、可见标注名与选中建筑，但不描述方位、遮挡、距离与画面构图；远景没有可见标注时只能提示「用侧栏索引浏览」。读屏用户仍无法形成空间印象。
2. **标签默认仍是全部**：分组跳转已把 Tab 范围缩到当前分类，但初次进入默认「全部」，仍需逐个走过全部标签才知道要分组；按钮文案「标注 · 全部」的可发现性待真人验证。
3. **信息卡正文仅中文**：英文界面下标题与字段标签为英文，正文仍是中文原文，尚未做全量翻译。
4. **搜索播报只报条数**：零结果与命中数会朗读，但不朗读「命中了哪些」；模糊命中的淡金色边线也没有对应的文字说明（仅视觉）。
5. **未做真实读屏测试**：本报告基于 DOM 结构与键盘操作自查，未在 VoiceOver / NVDA 下完整走查。
6. **对比度未用工具实测**：数值为按色值估算，建议用 axe 或 Lighthouse 复核。
7. **漫游仍主要依赖视觉**：准星点中建筑会播报名称，但没有连续的「当前朝向哪座殿」反馈；抬头看匾有浮层，读屏用户仍需靠点击才知道前方是什么。
